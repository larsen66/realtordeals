Правила для агента в этом репозитории.
Продукт и воронки — в [BRIEF.md](BRIEF.md).
Стек — в [docs/STACK.md](docs/STACK.md).
Не переизобретать стек.

## Что это

Операционный контур агентства недвижимости.
Лид приходит по каналу.
Менеджер квалифицирует.
Бот фиксирует.
В CRM появляется карточка.
Дальше подборка, просмотр, статусы, напоминания.

Пользователь бота — менеджер.

## Стек. Не менять без явного решения

- Язык: TypeScript, pnpm-монорепо.
- Фронт: Next.js App Router + shadcn.
- Бек: Express.
- Бот: grammY + `@grammyjs/conversations`.
- БД: Supabase. Клиент `@supabase/supabase-js`, без Drizzle.
- Очередь и фоновые задачи: Redis.
- Файлы: S3.
- STT: OpenRouter `openai/whisper-large-v3-turbo`, fallback `openai/gpt-4o-mini-transcribe`.
- Извлечение полей: OpenRouter через `@openrouter/ai-sdk-provider` + Vercel AI SDK `generateObject` + Zod. Не LangGraph.
- Хост: один VPS Timeweb Cloud (Москва), Docker Compose.
- Мессенджеры: Telegram Bot API. WhatsApp — в плане после Telegram. MAX и прочие API не подключать.

Секреты только в env / secret store.
Токены бота, OpenRouter, S3, Supabase не писать в git, в markdown и в промпты.

## Что делаем

1. Принять голос, текст, фото, ссылку.
2. Транскрибировать голос.
3. Положить данные в черновик формы продавца или покупателя.
4. Сверить обязательные поля.
5. Доспросить недостающее. Лишнее не выбрасывать молча.
6. Показать черновик и спросить подтверждение.
7. После подтверждения записать карточку.
8. Если обещан звонок — поставить напоминание менеджеру.

Несколько сообщений копятся в одну карточку, пока её не подтвердили или не сказали «новая заявка».

Лендинг пишет карточку покупателя в ту же БД.
CRM — карточки, статусы, подборки, просмотры.
Топики, рассылка, ссылка на объявление, фото без водяного знака — тот же контур.

## Домен

Говорить языком брифа.

- Карточка продавца и карточка покупателя — разные формы.
- Теги: `Продавец`, `Покупатель`, `Продажа`, `Покупка`.
- Продавец всегда с исходящего звонка.
- Без телефона карточку в CRM не отправлять.
- Статусы покупателя после квалификации: подборка → просмотр / дополнить подборку.
- Обещанный звонок — поле и джоба, не «бот запомнит».

Схемы форм живут в коде (`packages/domain`), не в промпте модели.
Промпт модели только заполняет эти схемы.
Промпт не является источником обязательных полей.

## Как писать код

- Сначала схема карточки и правила обязательных полей, потом хендлеры бота.
- Запись в CRM только после явного подтверждения менеджера.
- Исходный текст и транскрипт хранить рядом с карточкой.
- Идемпотентность: повтор того же апдейта Telegram не создаёт вторую карточку.
- Напоминания — строки в БД + Redis-джоба, не `setTimeout` в процессе.
- Веб и бот ходят в один Express API и одну доменную модель.
- Не добавлять зависимости «на будущее».

## Репозиторий

Пока кода нет, не создавать пустые пакеты.
Первый код: `packages/domain`, затем `apps/bot` и `apps/api`.

Не коммитить `.env`, ключи, дампы продакшена, голосовые клиентов.
Не писать CHANGELOG вручную, его нет.

Коммиты: по смыслу изменения, без Co-Authored-By и без «Generated with».
