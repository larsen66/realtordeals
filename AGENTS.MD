## Что это

Один операционный контур агентства, не набор отдельных продуктов.
Лид → квалификация менеджером → фиксация в боте → карточка в CRM → подборка, показ, дожим, сделка, напоминания.

Пользователь Telegram-бота — менеджер.
Покупатель и продавец — роли карточек, не пользователи бота.
Продавец всегда с исходящего звонка компании.

Говорить языком брифа: карточка, тег, черновик, подборка, показ, дожим, сделка, реферал, обещанный звонок.

## Не делать

- Отдельную модель или воронку для лендинга, бота и CRM.
- Одну форму на продавца и покупателя.
- Одну миниатюру CRM на продавца и покупателя.
- Смешивать температуру (холодный / тёплый / горячий) и этап (подборка / показ / дожим / сделка / реферал).
- Отдельную сущность для реферала или подборки вне карточки.
- Писать карточку в CRM без телефона.
- Писать карточку в CRM без явного подтверждения менеджера.
- Выбрасывать лишние поля молча: сказать, что понял, и спросить куда положить.
- Кладть в карточку или клиенту фото с водяным знаком Авито/Циан.
- Подключать WhatsApp, MAX и прочие мессенджерные API до явного решения.
- Класть обязательные поля только в промпт модели.
- Крутить STT, разложение в форму, парсинг объявления, напоминания, фото и рассылку в HTTP-запросе.
- Напоминания через `setTimeout` в процессе.
- LangGraph, Drizzle, второй бэкенд, второй язык.
- S3, MinIO и отдельное object storage.
- Зависимости «на будущее» и пустые пакеты.

## Контур

```
канал / лендинг / рассылка
        ↓
квалификация менеджером
        ↓
Telegram-бот: голос · текст · фото · ссылка
        ↓
черновик формы продавца или покупателя
        ↓
сверка обязательных → подтверждение
        ↓
карточка в CRM
        ↓
покупатель: подборка → показ → дожим → сделка / реферал
продавец: карточка объявления
```

Несколько сообщений подряд копятся в одну карточку, пока её не подтвердили или не сказали «новая заявка» / «это к той же».

## Карточка

Две формы. Схемы и правила обязательных полей живут в `packages/domain`.
Промпт модели только заполняет эти схемы.

Теги: `Продавец`, `Покупатель`, `Продажа`, `Покупка`.
От тега строятся заголовок, уведомление и форма.
Тег можно поставить голосом, кнопкой или топиком.

Исходный текст и транскрипт хранить рядом с карточкой.

### Поля

| Поле | Откуда | Правило |
| --- | --- | --- |
| Тип сделки | голос, тег | продажа / покупка |
| Тег роли | голос, кнопка, топик | продавец / покупатель |
| Телефон | голос, текст, лендинг | без него карточку не отправлять |
| Имя | голос, текст, лендинг | |
| Чья квартира | голос | личная сделка или чужой объект |
| Адрес, цена, комнатность | голос, объявление | |
| Площадь, этаж, этажность | объявление, звонок | часто копируются с площадки |
| Юридический блок продавца | звонок | ипотека, аресты, собственники, детские доли, маткапитал, занижение, цель и скорость продажи, что оставляют |
| Квалификация покупателя | звонок | что покупает, способ (своя ветка), локация, метраж/планировка, отделка, цель, что уже смотрели |
| Источник | лендинг, канал, голос | откуда пришёл покупатель |
| Бюджет | звонок | на миниатюре покупателя |
| Тип объекта | голос, объявление | на миниатюре продавца — «Тип» |
| Статус | менеджер | холодный / тёплый / горячий |
| Оплата | звонок | нал / ипотека |
| Этап | менеджер, бот | подборка / показ / дожим / сделка / реферал |
| ДР | голос, текст | дата рождения, на миниатюре у обеих ролей |
| Ссылка на объявление | текст | бот читает Авито и Циан и подставляет поля |
| Фото | загрузка или выгрузка | только без водяного знака площадки |
| Обещанный звонок | голос или поле | строка в БД + Redis-джоба |

Скрипт вопросов — в `BRIEF.md`. Не выдумывать другой скрипт квалификации.

После квалификации покупателя этапы той же карточки: подборка → показ → дожим → сделка. Реферал — этап той же карточки.
Температура холодный / тёплый / горячий — отдельное поле, не этап.

## Telegram-бот

Принимает голос, текст, фото, ссылку.
Транскрибирует голос. Раскладывает в форму. Доспрашивает обязательное.
Перед записью показывает структурированный черновик: всё верно?

Сам пишет статусы: карточка собрана, не хватает полей, ушла в CRM, ушла подборка, назначен показ, этап сменился, висит обещанный звонок.

Доставка: личный чат или группа с форум-топиками.
Топики не смешивать: продавцы, покупатели, продавец–менеджер.
Промпт топика задаёт роль. В топик продавцов не класть контур покупателя.

Идемпотентность: повтор того же апдейта Telegram не создаёт вторую карточку.

## Лендинг, CRM, рассылка

Лендинг: имя, телефон и обязательные поля заявки → карточка покупателя в ту же БД → исходящий звонок от имени компании.

CRM: список `/crm` — миниатюра, не полная форма. Поля миниатюры разные.
Продавец: имя, тип, адрес, телефон, ДР.
Покупатель: имя, телефон, источник, бюджет, тип объекта, статус холодный/тёплый/горячий, нал/ипотека, этап подборка/показ/дожим/сделка/реферал, ДР.
Полная карточка — та же модель. Веб и бот ходят в один Express API.

Рассылка — вход в ту же воронку покупателя, не отдельный продукт.
Ответ на рассылку попадает в ту же квалификацию и ту же карточку.

## Фото и объявления

Ссылка на Авито/Циан подставляет площадь, этаж, этажность, цену, комнатность, адрес.
Менеджер договаривает то, чего в объявлении нет.

Фото с площадки как есть нельзя: водяной знак показывает клиенту площадку, сделка уходит без комиссии.
Контур: ссылка или ручная загрузка → выгрузка без водяного знака → коллаж → карточка и свой сайт.

## Стек. Не менять без явного решения

- Язык: TypeScript, pnpm-монорепо.
- Фронт: Next.js App Router + shadcn.
- Бек: Express (`apps/api`).
- Бот: grammY + `@grammyjs/conversations`.
- БД: Supabase. Клиент `@supabase/supabase-js`, без Drizzle.
- Очередь: Redis (`apps/worker`).
- Файлы: диск на VPS, отдаёт `apps/api` `/files`.
- STT: OpenRouter `openai/whisper-large-v3-turbo`, fallback `openai/gpt-4o-mini-transcribe`.
- Извлечение полей: OpenRouter через `@openrouter/ai-sdk-provider` + Vercel AI SDK `generateObject` + Zod. Не LangGraph.
- Хост: один VPS Timeweb Cloud (Москва), Docker Compose.
- Мессенджеры: Telegram Bot API. WhatsApp — после Telegram.

Секреты только в env / secret store.
Токены бота, OpenRouter, Supabase не писать в git, в markdown и в промпты.

## Как писать код

1. Сначала схема карточки и правила обязательных полей в `packages/domain`.
2. Потом запись карточки в `apps/api`.
3. Потом фиксация в `apps/bot`.
4. Лендинг и CRM — те же карточки, не параллельная модель.
5. Worker — когда появляются STT, напоминания, парсинг ссылки, фото, рассылка.

Веб и бот ходят в один Express API.
Тяжёлое уходит в Redis, не крутится в запросе.

## Репозиторий

```
apps/web          Next.js: лендинг `/`, CRM `/crm`
apps/api          Express: /health, /cards, /leads, /statuses, /files
apps/bot          grammY — следующий пакет
apps/worker       Redis — когда появятся фоновые задачи
packages/domain   схемы форм — следующий пакет
```

`apps/web` и `apps/api` уже есть как каркас. Не плодить пустые пакеты.
Следующий код: `packages/domain`, затем `apps/bot` и запись карточки в API.

Не коммитить `.env`, ключи, дампы продакшена, голосовые клиентов.
Не писать CHANGELOG вручную, его нет.

Коммиты: по смыслу изменения, без Co-Authored-By и без «Generated with».
