# Telegram-бот Романа

## Учёт расходов OpenAI

При локальном polling-запуске команда `/usage` для разрешённых пользователей показывает накопительные токены и оценку USD отдельно для транскрибации, анализа голосового и текста. Журнал `apps/bot/.data/openai-usage.jsonl` переживает перезапуски и исключён из Git. В нём только usage, модель, тип операции, идентификатор запроса, длительность, статус и хеш ключа; аудио, текст клиентов и секреты не сохраняются. В Vercel-сборке события записываются в runtime-логи без локального файла; агрегированная сводка `/usage` для облака пока недоступна.

Учёт начинается с включения этой функции и охватывает только этот экземпляр бота. Расходы того же ключа из других программ не видны. Отсутствующий usage, неизвестная модель и сетевой сбой дают неизвестную стоимость, а не нулевую. Даже неполный ответ или отказ модели учитывается, если OpenAI вернул usage. Отказ записи журнала не вызывает повтор платного запроса.

Тарифы Standard проверены 2026-09-20: `gpt-4o-mini` — $0.15/$0.075/$0.60 за миллион входных/кешированных/выходных токенов; `gpt-4o-mini-transcribe` — $1.25/$5 за миллион входных/выходных токенов. Это локальная оценка, не баланс и не финансовый лимит. Источник: [OpenAI Pricing](https://developers.openai.com/api/docs/pricing). Фактические списания и баланс проверяйте в кабинете OpenAI. При изменении модели/тарифов обновите таблицу в `apps/worker/src/agent/usage.ts`.

Локальная структура в ветке `codex/vera-bot-structure`, от `7439abc`.

Сценарий: Роман выбирает покупателя/продавца → отправляет текст или голос → бот транскрибирует голос и извлекает поля через OpenAI → API проверяет поля по общей схеме и хранит черновик → бот показывает черновик → Роман исправляет или нажимает «Всё верно — сохранить» → API создает карточку CRM.

## Что уже реализовано

- grammY: личный чат, список разрешенных пользователей, команды `/start`, `/new`, `/draft`, `/help`.
- Прием текста и метаданных голосового; ограничения длины и размера.
- Отображение полей/ошибок из API, исправления, кнопки подтверждения конкретной версии.
- HTTP-клиент API с проверкой ответов, тайм-аутом, идентификаторами повторов и безопасными ошибками.
- Подключение к реальным маршрутам `/bot/v1`: черновики, сообщения, проверка версии и подтверждение создаваемой карточки.
- Постоянные черновики и идентификаторы обработанных обновлений в Supabase; подтверждение карточки выполняется транзакционно.
- Vercel webhook `/api/telegram` с проверкой Telegram secret token и фоновым завершением обработки через `waitUntil`.
- Изолированный модуль `apps/worker/src/agent`: прямые вызовы OpenAI для транскрибации и структурированного извлечения. Он не запускает worker и не пишет в базу.
- Деморежим и тесты без токенов, сети и клиентских данных.

## Режимы запуска

В API-режиме черновики хранятся в Supabase и переживают перезапуски функций. Локальные
тесты используют memory store. Отдельная долговечная очередь повторов пока не добавлена:
webhook завершает принятую обработку через Vercel `waitUntil`.

`BOT_MODE=api` не переключается незаметно на демо при ошибке. `BOT_MODE=demo` не использует OpenAI, не распознает голос и не сохраняет ничего в CRM. В нем текст вводится строками `Поле: значение`; свободный текст сохраняется заметкой. Учебные поля и правило телефона — только фикстура для интерфейса, не окончательная модель CRM.

## Проверка без ключей

Node.js 22+, менеджер пакетов проекта — pnpm 10.33.0.

После установки из корня репозитория:

```sh
corepack pnpm --filter bot lint
corepack pnpm --filter bot test
corepack pnpm --filter bot build
corepack pnpm --filter bot demo
```

Демо прогоняет настоящий обработчик обновлений grammY с подменой Telegram HTTP, показывая диалог в терминале.

## Запуск в Telegram

Скопировать `apps/bot/.env.example` в `apps/bot/.env.local`, локально заполнить `TELEGRAM_BOT_TOKEN` и `TELEGRAM_ALLOWED_USER_IDS`. Файл игнорируется Git. `BOT_MODE=demo` позволяет проверить кнопки на вымышленных данных. Затем `corepack pnpm --filter bot dev`.

С настоящим бэкендом выбрать `BOT_MODE=api`, заполнить `CRM_API_URL`, `CRM_API_TOKEN`, `OPENAI_API_KEY` и список ID. `CRM_API_TOKEN` должен совпадать с `BOT_API_TOKEN` в `apps/api/.env`. Локально `src/index.ts` запускает один polling-процесс. На Vercel используется `/api/telegram`; для него также обязателен `TELEGRAM_WEBHOOK_SECRET`. Пустой список разрешенных пользователей не открывает доступ всем: запуск запрещается.

Сейчас ключ OpenAI использует бот, чтобы получить файл голоса из Telegram, транскрибировать его и извлечь поля. При переносе в очередь ключ и `OpenAiAgent` переедут в worker. `@grammyjs/conversations` пока не добавлялся: состояние черновика живет в API, текущие команды работают на grammY без отдельного локального состояния диалога.

Фото, напоминания и групповые топики не входят в эту структуру.

## Меню и редактирование

Меню Telegram регистрируется при запуске: `/buyer` — Покупатель, `/seller` — Продавец,
`/edit` — Клиент CRM, `/draft` — Черновик, `/usage` — Расходы, `/help` — Помощь.
Обязателен только телефон. Остальные сведения можно не заполнять.
Для редактирования: `/edit +79991234567`, выбрать клиента, отправить правки и нажать «Сохранить».
Изменения обновляют существующую карточку; при изменении карточки в CRM нужно повторить поиск.

Перед обновлением API и бота применить `20260920150000_bot_edit_clients.sql`.
Она добавляет черновики редактирования и постоянный учёт расходов. История старых
runtime-логов автоматически не переносится.
